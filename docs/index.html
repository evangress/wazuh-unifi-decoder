Wazuh decoder and rules for Ubiquiti UniFi syslog

Send CEF logs from your UniFi Dream Machine, Cloud Gateway or Cloud Key to the Wazuh SIEM. Every UniFi CEF key gets decoded into a searchable field, and you get alerts for IPS threats, admin logins, config changes, WAN outages and offline devices.

What you get

UniFi Network can export system logs in CEF (Common Event Format) through Integration → System Logging / SIEM. Out of the box, Wazuh doesn't decode them. These two files cover that:

wazuh-unifi-decoder

ubiquiti_decoders.xml decodes all the publicly documented UniFi CEF keys, plus the undocumented ones that real controllers send, into about 150 fields. It also fills Wazuh's standard srcip, dstip and action fields.

wazuh-unifi-rules

ubiquiti_rules.xml has 33 rules (IDs 100010–100399) that turn decoded events into leveled alerts in the unifi group. Routine client connects and roams are stored without alerting.

Works with: UDM, UDM Pro, UDM SE, UDM Pro Max, UCG Ultra / Max / Fiber, Cloud Key Gen2 / Gen2 Plus, UniFi Express and self-hosted UniFi Network. Tested against UniFi Network 10.x and Wazuh 4.14.

Plenty of UniFi decoders you'll find online only match lines that start with CEF:. Real UniFi traffic arrives with a syslog header, so Wazuh treats CEF as the program name and those decoders never fire. This decoder handles both forms.

Install on the Wazuh manager

Run these steps on the Wazuh manager, as root.

1. Download the decoder and rules

cd /var/ossec/etc
curl -fsSL -o decoders/ubiquiti_decoders.xml \
  https://raw.githubusercontent.com/evangress/wazuh-unifi-decoder/main/ubiquiti_decoders.xml
curl -fsSL -o rules/ubiquiti_rules.xml \
  https://raw.githubusercontent.com/evangress/wazuh-unifi-rules/main/ubiquiti_rules.xml
chown wazuh:wazuh decoders/ubiquiti_decoders.xml rules/ubiquiti_rules.xml
chmod 660 decoders/ubiquiti_decoders.xml rules/ubiquiti_rules.xml

The default ossec.conf already loads every file in etc/decoders and etc/rules. You can also upload both files in the Wazuh dashboard under Server management → Decoders / Rules.

2. Accept syslog from the UniFi console

Add a listener inside <ossec_config> in /var/ossec/etc/ossec.conf. Wazuh silently drops syslog from any IP that isn't listed in allowed-ips.

<remote>
  <connection>syslog</connection>
  <port>514</port>
  <protocol>udp</protocol>
  <allowed-ips>192.0.2.10</allowed-ips>  <!-- your UniFi console's IP -->
</remote>

Open 514/udp in the firewall, for example ufw allow from 192.0.2.10 to any port 514 proto udp.

3. Restart and check for errors

systemctl restart wazuh-manager
grep -E 'analysisd.*(ERROR|CRITICAL|WARNING)' /var/ossec/logs/ossec.log | tail

4. Verify with wazuh-logtest

Paste this into /var/ossec/bin/wazuh-logtest. You should see decoder ubiquiti and rule 100301 at level 10.

Oct 10 16:00:00 unifi CEF:0|Ubiquiti|UniFi Network|10.6.106|512|Device Offline|8|UNIFIcategory=UniFi Devices UNIFIdeviceName=Lobby AP UNIFIdeviceModel=U6-Pro UNIFIdeviceIp=192.0.2.20 msg=Lobby AP went offline.

5. Point UniFi at Wazuh

In UniFi Network, open Integration → System Logging / SIEM, choose SIEM Server, enter the manager's IP and port 514, and pick the log categories to export. Leave the debug option off. It sends verbose non-CEF logs that include device auth keys.

Decoded fields

Each CEF key gets its own sibling decoder, so a key that's missing from one message never blocks the others. UNIFIfooBar keys become unifi_foo_bar. Here are some of the most useful ones:

FieldFrom
event.name, event.id, event.severityCEF header
unifi_category, unifi_sub-categorySecurity, Audit, Client Devices, UniFi Devices, Internet and WAN, …
srcip, unifi_client_ip, unifi_client_mac, system_nameClient identity
dstip, dstport, unifi_connected_to_device_nameThe AP or switch a client is attached to
unifi_admin, unifi_settings_section, unifi_settings_changesAdmin audit trail
unifi_wan_id, unifi_wan_isp, unifi_wan_latencyWAN health
unifi_wifi_name, unifi_wifi_rssi, unifi_bssidWireless details
unifi_device_name, unifi_device_model, unifi_device_versionUniFi hardware

The full list is in ubiquiti_decoders.xml.

Testing

The decoder repo includes a throwaway Docker lab that runs a Wazuh manager and mounts both repos, plus samples/events.log: anonymized real UniFi events, each annotated with the decoder, rule, level and fields it should produce.

git clone https://github.com/evangress/wazuh-unifi-decoder
git clone https://github.com/evangress/wazuh-unifi-rules
cd wazuh-unifi-decoder
docker compose -f lab/docker-compose.yml up -d
./test.py
docker compose -f lab/docker-compose.yml down -v

You can also point a live controller at the lab. See lab/README.md.

FAQ and troubleshooting

Nothing arrives in Wazuh

Check that the console's IP is listed in allowed-ips and that 514/udp is open. Run tcpdump -ni any udp port 514 on the manager to see whether packets reach it at all.

Events arrive but don't decode or alert

Set <logall_json>yes</logall_json> temporarily and look at /var/ossec/logs/archives/archives.json. If "decoder" is empty, the decoder isn't installed, or it's an older version that only matches bare CEF: lines.

My custom rules already use IDs 100010–100399

Renumber one of the two rule sets so the IDs don't overlap. Wazuh logs a warning for duplicate rule IDs.

An event type isn't decoded or has no specific rule

Open an issue or pull request with an anonymized sample line. UniFi's real output differs from its documentation, so live samples are the most useful contribution.
